**What the second implementation caught.** Three things in the kit, none
in the model. The exporter's tier 3 had evaluated three cameras on one
grid, so the second and third cameras' flags carried the first's state;
the runner opens a fresh grid per camera, and now so does the exporter.
"Present" needed a definition (bits held versus bits present); the
fixture now carries both counts from the snapshot. And a ledger line
that is not an event (the forged case appends one) crashed Python's
sort until it learned the reference's tolerance.

**What was built.** `stateCanonical` and `stateDigest` (state without
the self-test outcome) in `src/verify.ts`; the exporter (slot tables as
data, four sealed and signed packs, two operation scripts under a fixed
clock, three cameras); the TypeScript runner; `kit/python/vpb.py` (the
container's operations with report-then-apply, derived links from
`slots.json`, replay, packs, seals, the `Canon` JSON writer that prints
whole-number floats as integers), `ed25519.py`, `run_kit.py`;
RUNNING.md written for a stranger with the fixtures alone; the CI job on
Python 3.12.

**Decisions (ADR 0018).** The fixtures are the contract, neither
codebase is. The state digest is the kit's digest because the scene
digest carries the camera's self-test outcome, which is tier 3. Python
for reach, not preference.

**Not done.** Tier 3 in Python: the render self-tests of §8 are the
stretch. The signed fixtures change bytes per export; a fixed test key
checked into the repository would make them stable, at the cost of a
key in the repository, which the project has avoided so far.
