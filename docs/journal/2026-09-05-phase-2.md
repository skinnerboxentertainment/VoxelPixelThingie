# 2026-09-05, Phase 2: Reference image

**Merged.** Canvas 2D demo with pixel, tile, and cube modes, Vite for the
demo workspace, Playwright with three golden screenshots, e2e in CI.

**Oracle, Verified this session.** Six Playwright tests pass from a cold
server with the CI flag set: the carved scene has 485 bits, each mode's
HUD matches the model's render list, each mode matches its golden with the
HUD masked, pixel mode shows exactly 64 faces, and clicking a bit removes
it. Whether the goldens hold on Linux Chromium is decided by the CI run on
the PR, not by this entry.

**What the reference image shows.** The model, not the renderer, decides
what is drawn. Adjacent bits hide their shared faces, edges, and vertices
through links, so an 8×8×8 block renders as one smooth solid with glowing
seams only along the outer silhouette and the carved notch. Node counts
per mode from the HUD:

| Mode | Faces | Edges | Vertices | Nodes of 12,610 |
|------|------:|------:|---------:|----------------:|
| pixel | 64 | 38 | 6 | 108 |
| tile | 192 | 33 | 6 | 231 |
| cube | 192 | 41 | 5 | 238 |

The pixel count is the one worth remembering: 64 faces for an 8×8 top
layer, one per column, with the carved corner exposing lower faces in its
3×3 patch. The bit is a pixel from straight above.

**Two things fixed on the way.**

- Playwright's `webServer` was given `npm run build && npm run preview` and
  served a page that did not exist. Splitting the build into a `pretest:e2e`
  script and leaving Playwright only the preview fixed it. Root cause not
  proven; the split is more robust regardless.
- The HUD overlapped the captured canvas and its font would differ on Linux.
  Masked in the screenshot assertion.
