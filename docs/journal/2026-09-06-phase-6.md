**Design decisions made in flight.**

- The sink projects a whole batch before writing anything, so a batch it
  cannot project writes nothing. Found by the resume test.
- `openScene({ attach })` attaches a sink after rebuild and the grid
  continues its sequence from the manifest, so a resumed sink sees only
  new events. The earlier `{ sink }` option still exists and receives the
  replay, which the demo's save path relies on.
- Any write drops `manifest.hashes`; sealing is a publish-time act.
- Ledger appends are batched per bit and run with bounded concurrency,
  which the browser's file system needed and the disk store did not mind.
