**What was built.** `src/der.ts` (TLV reader and writer for the shapes the
tokens contain, nothing more), `src/rfc3161.ts` (request, response, CMS
verification with WebCrypto, certificate lookup by issuer and serial or
by subject key identifier), `src/witness.ts` (contract, notary,
authority, verifier with anchoring), `src/did.ts` rotations,
`src/verify.ts` witnesses and the chain walk with the `retired` state,
`scripts/rotate-key.ts`, `--witness` on `scene:sign`, witness lines in
`scene:check`, the witness row in the reader, `tests/witness.test.ts`,
`tests/fixtures/rfc3161/` (the data, the request, both responses).

**Decisions (ADR 0013).** The witness binds the signature's digest, not
the files, so one proof covers the whole seal. Anchoring is the caller's
trust list, not a chain walk to a root; the verdict says "unanchored"
rather than pretending. Rotations live in the DID document as a plain
JSON extension so the chain travels with the key. A retired key's seal
verifies unless a witness places it after retirement.

**The reference scene's witness is a notary, not a public authority.**
PLAN-4.md lists the public witness as Oscar's decision: an RFC 3161
token on the reference scene is a permanent public record. The notary
key is `~/.config/vpb/notary-reference.jwk` (never printed); it is
unanchored to anyone but us, which the report says. When the decision
is made, the command is one flag:

```
npm run scene:sign -- <folder> --key <container jwk> --host ... --witness rfc3161:http://timestamp.digicert.com
```

**Not done.** RSA-PSS tokens, SHA-1 imprints, and certificate chain
validation are refused or not attempted, by name. The reference
container's key has not been rotated; rotation was exercised with
throwaway keys only. The witness time is displayed by the reader but the
reader carries no trust list, so its witnesses are always "unanchored".
