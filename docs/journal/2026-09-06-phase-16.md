# 2026-09-06, Phase 16: A container as a body

**Merged.** The worker image, the Docker host helper, ADR 0011, and the
container oracles (this entry's PR, ticket #97). Asked and built in one
sitting: Oscar asked whether a bit could be a data store connected to a
Docker container; the answer was that it already stores by content id
and runs work through a contract, so a container is one more body.

**Oracles, Verified this session, Docker Desktop 29.6.2 on Windows,
first shot.**

| Oracle | Result |
|--------|--------|
| Worker image built from the repository root | 96.8 s |
| Worker container ready over a bind-mounted scene folder | 8.1 s |
| Sixty-four jobs on the worker container | all passed, exactly one record per step in every ledger; 115.2 s |
| Container killed with SIGKILL inside a slow job; a second started | the successor finished it 12.1 s after the kill; four records; workflow COMPLETED |

**The number that matters.** The same sixty-four jobs took 2.7 s with the
worker in a process on the host and 115.2 s in the container. The work is
the same; the difference is the ledger. Every record step reads the
bit's ledger from the scene folder and flushes it, and that folder is a
Windows path bind-mounted into a Linux container through Docker Desktop's
file sharing, which is slow per operation. A scene inside the container's
own filesystem, or a store that is not a folder, removes it; the number
is recorded, not hidden.

**What was built.** `docker/worker.Dockerfile` (Node 22, the runtime
dependencies, `scripts/durable-worker.ts` unchanged as the entrypoint over
`/scene`), `.dockerignore`, `scripts/docker-host.ts` (build, the engine's
dev server as a container on a `vpb` network, start, kill, stop, logs,
and a `--down`), `tests/docker.test.ts` opting in with `VPB_DOCKER=1`,
ADR 0011.

**Decisions (ADR 0011).** No new contract and no new backend class: the
container is a body for the durable worker, and Phase 15's workflow ids
and idempotent record steps are what make the kill test hold. The test
opts in because the image takes a minute and a half to build and CI
runners vary; the journal is where the numbers live.

**Not done.** The image is not published; a store backend that keeps the
ledger inside the container or on an object store would make the
container path as fast as the process, and is the obvious next
measurement.
