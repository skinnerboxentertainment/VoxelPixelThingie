# 2026-09-05, Phase 1: Model hardening

Same calendar day as Phase 0; the plan's Days 2 and 3 compressed into one
session.

**Merged.** Grid, render list, container-minted ids (#17). Event sink,
recording sink, replay, `destroyed` event (#18). Back-facing tolerance and
the emission schema decision (#19). Property tests and benchmarks (this
entry's PR).

**Oracles, all Verified this session.**

- `Grid.fill(8,8,8)` reproduces the pairwise oracle: 384 faces, 216 bits
  asleep. `renderList` length equals enabled node count.
- Replay of a recorded carve, restore, move, three emits, annotate, and
  destroy on an 8×8×8 is deep-equal to the live grid, fields and render
  flags both.
- Camera in the +Y plane keeps +Y enabled; 0.01 behind disables it.
- Six fast-check properties at 1000 runs each pass, plus one exhaustive
  property: removing any one of the 27 bits in a 3×3×3 leaves every
  remaining link mirrored. That property is the executable form of the
  exit-review claim from PLAN.md §3, so no separate `/falsify` run was
  made; the test is the falsification attempt and it found nothing.
- Test count 23 to 42. Coverage on `src/` 98.6% lines.

**Benchmarks, this machine, Node 22, one run each.** Numbers are
measurements, not targets.

| Size | Bits | evaluate after camera move, median | renderList, median | Heap after fill | Fill time |
|------|------|-----------------------------------:|-------------------:|----------------:|----------:|
| 8³ | 512 | 0.16 ms | 0.06 ms | 7 MB | 42 ms |
| 16³ | 4,096 | 1.9 ms | 0.35 ms | 49 MB | 171 ms |
| 32³ | 32,768 | 17.5 ms | 4.9 ms | 403 MB | 1.5 s |
| 48³ | 110,592 | not timed | not timed | 1,105 MB | 8.7 s |
| 64³ | 262,144 | out of heap at the default limit | | est. 3.3 GB | |

Roughly 12.6 KB per bit. That is 26 node objects, each with an emission
object and a links array, per bit.

**What this changes downstream.**

- PLAN.md §5 wanted 32³ orbiting under 16.7 ms p95. The CPU self-test alone
  is 17.5 ms median at 32³ when every bit re-evaluates on camera move, and
  most of that is iterating bits that are enclosed and skip early. Phase 3
  will either evaluate only bits in the render cycle, or accept 16³ for the
  live orbit and show 32³ static. Decide at Phase 3, not now.
- 64³ is not a demo target on this model. REPOS.md already names bitECS as
  the flat-array replacement when this bites. It has now bit, on paper.
- `Grid.fill` is superlinear because every `link()` scans `isLinkedTo`
  across all 26 nodes' link arrays. Cheap to fix later with a neighbor set
  per bit. Not fixed now; not in Phase 1's scope.

**Corrections.** The old test label "+Y is edge-on" was wrong: the camera
was 0.5 below the face plane. Fixed in #19. Ticket #14 assumed `linked`
and `unlinked` are derivable on replay; the oracle verified one sequence,
not the general claim, and the PR says so.

**Risk.** Event volume: a dense fill records a `linked` event per node pair
per side, roughly ten thousand for an 8×8×8. Retention is open question 5
in SPEC.md.
