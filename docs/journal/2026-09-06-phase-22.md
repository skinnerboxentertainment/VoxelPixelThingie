**What the SBOM oracle found.** `npm sbom --omit dev` drops production
packages that a dev dependency also depends on (`@grpc/grpc-js` under
`@temporalio/client`, for one), so its "production" list is not the
lockfile's. The release writes the whole tree, dev included, which is
the set npm states exactly, and the test compares that.

**What was built.** The manifest (version, commit, epoch, every file's
SHA-256 and size under `dist` and `dist-reader`, one digest over the
canonical text); `release:build` pinning `SOURCE_DATE_EPOCH` to the
commit's time and writing the SBOM beside the manifest; `release:attest`
reusing the container key and the `Witness` contract; `release:verify`
reusing the seal's verification path (DID document, rotation chain,
`retired`, witnesses) and reporting each source on its own line; the CI
job that builds the head commit and uploads its manifest; RELEASING.md;
`tests/release.test.ts`.

**Decisions (ADR 0016).** The digest covers the built files, the commit,
and the epoch, not the SBOM. The attestation that needs no account is
the container key plus witnesses; the public provenance attestation
(in-toto/SLSA on the host's transparency log) is Oscar's decision, and
the verifier says "not checked" until it is made rather than pretending.

**Not done.** No public provenance; no release cut. The attestation
here was made with the reference scene's container key because the
project has no separate release key yet; whether a release key should
be its own DID is a small decision for the first real cut.
