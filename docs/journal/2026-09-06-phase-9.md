**What the repository taught the export.**

- **Identifiers.** The plan said `urn:uuid:`. OpenEPCIS runs every `urn:`
  in an epcList, a readPoint, or a source through its GS1 identifier
  translator and rejects what is not a GS1 URN. Probed with single events:
  `urn:uuid:` and `urn:vpb:` fail in all three places, `https://` URIs
  pass, GS1 Digital Link URIs pass, and the event id is not translated.
  Bits, containers, and actors are now web URIs under the project
  namespace; the prefixes are options. ADR 0008.
- **Extensions need a schema.** Events carrying `vpb:` fields are refused
  with "No JSON schema found for namespace" until the namespace is
  registered at `/userExtension/jsonSchema`. The schema is vendored at
  `vendor/epcis/vpb-extension-schema.json` and the capture script
  registers it first; a second registration answers 500 "already mapped",
  which the script reads as done.
- **Capture is asynchronous, and the job record lags.** A capture answers
  202 with a job URL. The job's own duration is under two seconds alone
  and up to ten with sixteen in flight, but its `running: false` lands
  about 30 seconds after the POST, on a cadence that setting the Kafka
  Streams commit interval to one second did not move. Waiting for the job before
  sending the next chunk is the safe protocol; eight in flight is the
  fastest that lost nothing.
- **Sixteen in flight loses captures.** The first burst of sixteen POSTs
  produced `SRMSG00034: Insufficient downstream requests` and sixteen jobs
  stayed running with zero events for good; the same run logged
  `ConcurrentModificationException` while serializing to the
  `epcis-event-captured` topic. With eight in flight the small scene
  logged 36 such serialization-failure lines and every event still
  queried back, so that path is notification, not storage. The script
  defaults to one in flight and documents why.
- **Limits.** Captures over 100,000 bytes answer 413, so the document goes
  in chunks under 90,000 bytes; `perPage` is capped at 100 and the next
  page is a `Link` header, not the `GS1-Next-Page-Token` header the
  standard names.
- **Transient failure.** One run died on a single `fetch failed`; the
  script now retries network failures with backoff, and a retried chunk
  that had already landed fails as duplicates, which it counts once.

**Plan table corrections.** `passport` rides an extension, not ilmd, which
EPCIS 2.0 allows on ADD only; identifiers are web URIs. Both rows were
corrected rather than left as intent.

**Not done.** OpenEPCIS's query side was not exercised beyond counting:
no `MATCH_epc` or time-window queries. The GS1 Digital Link form for a
physical bit is an option, not a default.
