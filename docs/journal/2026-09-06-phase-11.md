**What was built.** `src/keys.ts` (Ed25519 through WebCrypto, JWK in and
out, base64url), `src/did.ts` (DID names, method URLs, documents with a
`JsonWebKey2020` verification method and service endpoints, resolution),
`sealScene` with a signer and `verifyScene` with a resolver reporting
`unsigned`, `verified`, `forged`, or `unresolved`, `scripts/keygen.ts`
(private JWK to a path outside the repository, never printed),
`scripts/sign-scene.ts` (re-seal and write `did.json`),
`scripts/mirror-check.ts` reporting the signature state and surviving a
store that no longer parses. SPEC v0.7 §10.3 and §10.9.

**Decisions.** One key per container, not per bit; a bit's DID is its
container's DID plus a path, so 512 bits need no 512 documents. The
signature covers the scene id, the sorted ids, and every file hash, so
the two forgeries above fail in different places: a changed file fails
its hash, a rewritten manifest fails the signature. `unresolved` is not a
failure, because the hashes stood on their own before this phase and
still do.

**Not done.** The reference container's private key exists on this
machine beside the Pinata token. Its DID document is written next to the
scene export and is not yet served anywhere, so `did:web` does not resolve
over the network: 11.2.
