CI's software GL stack measured the 8³ save at 1,980 ms, about 2.4 times
this machine; the e2e gates are the ticket's numbers, 3 s per step, not
the laptop's.

**What was built, and the turn it took.**

- Save writes one packed file instead of 1,025 files. That alone took the
  round trip from 27.5 s to under 2 s.
- The worker store writes through `FileSystemSyncAccessHandle` in a
  dedicated worker. The first design seeded the whole scene through it,
  one file per bit, and timed out at a minute: opening a synchronous
  handle costs tens of milliseconds regardless of how little is written,
  so a thousand files are slow whichever thread opens them. The handles
  are the right tool for small edits and the wrong tool for seeding.
- The fix is a layered scene: a packed base written once, plus a delta
  folder holding only the bits changed since, joined by an `OverlayStore`
  whose reads fall through, whose writes go up, and whose first append to
  a path copies the base text up. `openScene`, `SceneSink.resume`, and the
  seal see one ordinary scene. Four unit tests state its behavior; the
  reopen-after-edit test proves the digest holds across base plus delta.

**Bugs found on the way.**

- The worker posted replies through a detached `postMessage` reference,
  which throws "Illegal invocation" inside a worker and would have
  swallowed every reply. Caught by a probe that captured the page's
  console; fixed by calling it on the scope.
- Two patch scripts failed on anchors Biome had reformatted. The habit
  now is to read the real text first.

**Not done.** Multi-tab coordination; two tabs autosaving the same root
would interleave. Safari private mode has no OPFS and the demo says so.
