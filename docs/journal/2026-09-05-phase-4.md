**Merged.** PixiJS v8 demo: two 16×16 layers, pixel mode straight down Z
with glowing borders and corner beads, a carved window and diagonal
revealing the darker back layer, tile toggle, click to remove. One model
change that the demo forced (below).

server with CI=1: 491 bits (512 minus 21 carved), pixel mode shows

**The model change.** The pixel-mode oracle failed first: side faces of the
carved cells were rendering. The cause was in the model, not the demo. An
orthographic view was being represented as a very distant point, so a
side face on the near side of the scene center had a cosine of about
+2e-4 against it and passed the inclusive facing test, while the same
face on the far side did not. The Canvas demo's 8×8×8 oracle of 64 faces
had passed only because its notch happened to sit on the far side.

Fix: `Camera` gains an optional `towardCamera` direction. When present,
facing is tested against the direction and is exclusive at the plane,
because an edge-on node has no projected area and there is no viewpoint
for it to flicker at. Straight down an axis this leaves exactly the nine
+Z-side nodes, which is the claim RESEARCH.md made for pixel mode and the
spec now states in §8.2. A unit test asserts the nine slots by number.
The Canvas goldens did not change.

**Not done.** No golden for the PixiJS stage; the plan's risk table chose
DOM assertions plus a non-blank check for GPU-rendered canvases, and that
is what shipped. Parallax in pixel mode is a five-pixel screen shift per
layer, a cue rather than a projection.
