**The number that changed the design.** The first cut embedded the pack
as plain JSON: 3.00 MB for the built-in scene and 17.15 MB for reference-8,
whose 54,392 events are mostly link records. That failed the 4 MB oracle
by a factor of four. Ledgers are repetitive text, so the pack now goes in
gzipped and base64-encoded and the page inflates it with the browser's own
`DecompressionStream`; reference-8 came down to 0.92 MB, an eighteenfold
saving with no dependency added. The plain form stays as an option and the
unit test covers both.

**What was built.** `demo/reader/` (list, passport, emissions, history,
verify, the SPEC and DID document in disclosure sections; keyboard
focus styles, a live status region, labelled tables); `vite.reader.config.ts`
with the single-file plugin, build-time only; `scripts/reader-scene.ts`
(`builtin` makes a signed reference scene under a throwaway DID for the
oracle, `--tamper` flips one digit, `--plain` is not offered on the CLI:
gzip is the default and the only published form); `tests/reader.test.ts`
and `tests/e2e/reader.spec.ts` with `@axe-core/playwright`; a Reader
card on the demo index and a link from the passport page.

**Decisions (ADR 0012).** The reader is a wrapper around an unchanged
`vpb-scene-pack/1`; verification is `src/verify.ts` imported, not
reimplemented; "verified against the embedded document" and "verified by
resolving the DID" are kept as distinct wordings because they are distinct
claims. The embedded document is as trustworthy as the file it came in;
Phase 18's witness is what makes the offline verdict stand on its own.

**Not done.** The in-app browser here could not open `file://` URLs, so
the offline oracle ran in Playwright's Chromium only; Firefox and Safari
are Trusted to inflate gzip through `DecompressionStream` and to run an
inline module script from disk, not Verified. The 4 MB oracle was met by
compression, not by compaction; a scene ten times larger would need §10.7.
